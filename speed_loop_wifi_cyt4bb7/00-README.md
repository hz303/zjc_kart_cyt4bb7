# 6.speed_loop_wifi_cyt4bb7 · 双电机闭环速度环（WiFi-SPI 遥控）

> 基座：`4.motor_wifi_verify_cyt4bb7`（WiFi-SPI 链路 + 上位机 KartHost，已验证跑通）
> 控制：单电机速度环的 LQI 结构 + 保护，扩成**左右双电机闭环**
> 与基座的差别：**取消了开环占空比通道**。上位机只下发「目标转速 rps」，闭环完全在车端跑。
> 开环标定请用 `5.speed_loop_vofa_cyt4bb7`（串口 + VOFA+）。

## 1. 硬件接线

| 项 | 引脚 | 库里的名字 |
|---|---|---|
| 左电机 PWM | **P10_2** | `TCPWM_CH30_P10_2` |
| 左电机 DIR | **P10_3** | 普通 GPIO |
| 右电机 PWM | **P05_2** | `TCPWM_CH11_P05_2` |
| 右电机 DIR | **P05_3** | 普通 GPIO |
| 左编码器 脉冲 | **P17_3** | `TC_CH58_ENCODER_CH1_P17_3` |
| 左编码器 方向 | **P17_4** | `TC_CH58_ENCODER_CH2_P17_4` |
| 右编码器 脉冲 | **P19_2** | `TC_CH27_ENCODER_CH1_P19_2` |
| 右编码器 方向 | **P19_3** | `TC_CH27_ENCODER_CH2_P19_3` |

- 编码器引脚与库例程 `E2_01_encoder_dir_demo` 的「编码器1 / 编码器2」完全一致。
- 右电机的 `P05_2/P05_3` 对应 **CH11/CH12**（不是 CH05 —— CH05 是 P02_2/P04_1，查枚举时容易看错）。
- 两路 PWM 都在 TCPWM0 的 GRP0 里，该组的时钟分频是共享的 → **同组内必须同频**。本工程两路都是 17 kHz，没问题。
  将来要在同一组上接 50 Hz 舵机，**必须实测确认**，不能想当然。
- dir 模式下 DIR 脚被库配成 **下拉输入**（`CY_GPIO_DM_PULLDOWN` + GPIO）。若编码器方向线是开集输出，
  悬空时电平会恒为 0 → 测速符号恒定，此时要把该脚改成上拉。

## 3. 控制律与参数

```
u = u_ff(r) + k_v·(r − v) + k_z·∫(r − v)dt
u_ff(r) = r/K + u0·sign(r)
```

| 参数 | 值 | 来源 |
|---|---|---|
| K | **6.46** rps/占空比 | 本车台架 8 点稳态拟合（残差 ≤ 0.022 rps），另一组 4 点阶梯互证到 1% |
| u0 | **0.033** | 同上 |
| τ | ≈ 24 ms | 各平台阶跃拟合（13~33 ms） |
| 反馈等效延迟 | ≈ 10 ms | 4 点滑窗 7.5 ms + ZOH 2.5 ms |
| k_v / k_z | **0.164 / 2.32** | PM=60°、α=6 反解后整体砍半 |
| 闭环实测 | 稳态误差中位 **±0.01 rps** | MM32 台架，目标 0.5~1.5 rps |

> 这组数只对**这台驱动电机**（要装到卡丁后轮上的那台）成立。
> 项目里另一台「转向电机」K ≈ 215，差 33 倍，**一个数都不能互抄**。
> K 随负载变：空载 K 最大（稳定性最差工况），落地带载后 K 变小、u0 变大 → 前馈偏小由积分补足（偏保守）。
> **落地后建议重测一组稳态点回填。**

## 4. 编码器每转计数（cpr）

本车实测：编码器 **1024 线**（只数上升沿）+ 电机轴 49 齿带动 27 齿（增速 49/27）
⇒ **每电机转 = 1024 × 49/27 = 1858**（轮子与电机同轴，所以也是每轮转计数）。

标定：清零 `pos_l`/`pos_r` → 单方向手转**电机轴**整 10 圈 → `cpr = pos 增量 / 10`。

## 5. 上电标定三步（顺序不能颠倒）

1. **电机方向**：给一个小的正目标，确认电机朝「车前进」方向转；反了改 `minv_l` / `minv_r`。
2. **测速正负**：判据是「正命令 ⇒ 该侧 v 为正」；反了改 `inv_l` / `inv_r`。
3. **每转计数**：按第 4 节标定，改 `cpr_l` / `cpr_r`。

以上五个参数都在上位机滑条上，**在线改、不用重烧**。

## 6. 保护（五道门，全部满足才允许出力）

| 门 | 判据 |
|---|---|
| 1 上位机说过话 | 上电以来至少收到过一帧下行（没有就绝不自己转） |
| 2 使能位 | `bit1`（电机）且 `bit2`（总使能）都置位 |
| 3 失联自停 | `auto_stop=1` 且链路超过 `lost_ms` 无下行 → 目标归零 |
| 4 主循环心跳 | 超过 200 ms 没心跳（主循环卡死）→ 直接停机 |
| 5 占空比限幅 | `duty_limit%` 压给控制器，`motor_drv` 里还有一道 `|u| ≤ 1` |

门控不过时**输出严格 0 且清积分** —— 否则"被保护停住"期间误差一直累积，一放开门就是一次猛冲。
保护状态位图在遥测通道 `safety`（0 = 一切正常）：`0x01` 没收到过下行 / `0x02` 未使能 /
`0x04` 失联 / `0x08` 无心跳 / `0x10` 配置非法 / `0x20` 本拍被限幅夹过。
`0x04 / 0x08 / 0x10` 发生时主循环会打印一行 `[!!] SAFETY EVENT`。

## 9. 串口自检

上电第一秒应看到 `[##] UART OK  dual motor speed loop (WiFi)`，之后每秒一行状态：

```
[    12 s] err=0 online=1 en=0x0006 rx_age=12ms safe=0x0000 | L tgt=0.50 v=0.49 | R tgt=0.50 v=0.50 | cpr=1858/1858
```

- 只要这行在跳，说明主循环活着、时钟活着、串口活着。
- `online=0` / `safe=0x04` ⇒ 上位机没在发心跳（KartHost 的心跳间隔是 100 ms）。
