# 上电标定卡 · 双电机速度环（WiFi）

> 适用工程：`A_zjc_project/6.speed_loop_wifi_cyt4bb7`
> 目的：把「电机方向 / 测速正负 / 每转计数」三件事一次定死。
> **顺序不能颠倒**，而且**第 2、3 步必须在关掉使能的状态下做**。

---

## 为什么必须标

`v` 是环路唯一的反馈。只要 **`u > 0` 却让 `v` 变负**，环路就是**正反馈**：

- 控制器想把 `v` 拉到目标，于是不断加大 `u`；
- 而 `u` 越大 `v` 越负，误差越大；
- 结果一路顶到占空比限幅，**目标写 0 也停不下来**。

**自激的签名（一眼认出）**：

| 现象 | 含义 |
|---|---|
| `target = 0` 但 `v` 跑满、计数一直走 | 正反馈 |
| `safety = 32`（`SAFE_BIT_OVER_LIM`，非致命位） | 输出长期被限幅夹住 |
| `v` 的绝对值 ≈ `K·(lim − u0)` ≈ `6.46 × (0.30 − 0.033)` ≈ **1.72 rps** | 就是"限幅允许的最高速" |

---

## 第 0 步 · 先压限幅、关使能

```
1) 关【整体使能】（或急停）        -> 输出归 0，轮子滑行
2) 占空比上限 -> 20                -> 标定期间有任何意外都跑不快
3) 确认 实时值 里 enable = 0
```

---

## 第 1 步 · 校验 cpr（每转计数）

判据：**手转【电机轴】整 10 圈 → `posL` 增量 = cpr × 10**

```
发 u（或用另一个工程的 pos 清零），把 posL 清零
手转【电机轴】整 10 圈（单方向、平滑、不回抽）
读 posL 增量 / 10  ->  应是 1858
```

本车实测值：**1858** = 1024 线 × 49/27（编码器在 27 齿轴上，电机轴 49 齿）。
- 对得上 → 不用改；
- 差 1.8 倍 → `cpr` 填错轴了（转的是编码器轴，不是电机轴）。

> 交叉验证：限幅 30% 时 `v_max = K·(0.30 − u0) ≈ 1.72 rps`。实测能到这附近，说明 `cpr` 和 `K` 都对。

---

## 第 2 步 · 定「测速正负」（手转，**关使能**）

```
手把【左轮朝车前进方向】慢慢转，看 左轮实测 v_l
```

| 看到的 | 说明 | 动作 |
|---|---|---|
| `v_l > 0` | 编码器符号已经是对的 | 不动 `编码器|测速取反L` |
| `v_l < 0` | 编码器符号反了 | 把 `编码器|测速取反L` 拖到 **1** |

右轮同理（`编码器|测速取反R`）。**右轮编码器现在没接，跳过。**

---

## 第 3 步 · 定「电机方向」（**这一步和第 2 步合起来才闭环**）

标定完第 2 步后，`v` 的正负已经和"前进"一致了。此时：

- 若环路稳定（给正目标 -> `v` 收敛到正）→ 结束，`电机|极性翻转L` 保持 0。
- 若环路还是自激 → 说明 `u > 0` 推的方向和"前进"相反 →
  把 **`电机|极性翻转L` 拖到 1**。

> **两个开关二选一，别都翻。** 翻两次等于没翻。
> 编码器与电机是机械连着的：翻电机方向会把编码器读数一起翻，所以**翻一个就能同时修好两件事**。

---

## 第 4 步 · 验证（**这一步过了才算标定完成**）

```
占空比上限 -> 30
左轮目标   -> 0.3
点【整体使能】-> 再点【电机使能】
```

必须同时满足：

| 检查项 | 期望值 |
|---|---|
| `v_l` | 稳定收敛到 **+0.30**，不振荡、不反向 |
| `u_l` | ≈ **8%**（= 0.3/6.46 + 0.033） |
| `safety` | **0** |
| `enable` | **6** 或 14（bit1 电机 + bit2 整体） |
| 手轻推轮子加阻力 | `v_l` 掉一点后拉回，`u_l` 上去一点 |

再试 `左轮目标 -> 0`：`v_l` 应在 1 s 内降到 0，`u_l` 回 0 附近。

## 常见对不上

| 现象 | 原因 |
|---|---|
| `v` 有**周期性向下尖刺**（0.3~0.7 rps，平均值却跟得很准） | **一次 DIR 毛刺连丢 2 拍**（不是拾噪！）。算账：1.4 rps 每拍 11.5 个计数，丢 1 拍 = 0.35 rps 凹陷。已由 `ENC_DIR_DEBOUNCE` 修掉；看串口 `fL`/`gL` 每秒涨多少确认 |
| `v` 抖动很大、计数自己走 | 编码器脉冲线拾噪（靠近 PWM 线）。先做第 2 步：关使能后 `v` 是否回 0；不回 0 就是噪声 |
| 给正目标，轮子**反向**飞转 | 第 2/3 步顺序反了，或两个开关都翻了 |
| `safety = 2` | 使能位没齐：**电机使能 + 整体使能**两个都要亮 |
| `safety = 4` | 失联（上位机没在发心跳 / UDP 端口不对） |
| `safety = 8` | 主循环心跳丢了（固件卡死） |
| `safety = 16` | 配置自检不过（上电时串口会打印 `[##] CONFIG BAD`） |
| `safety = 32` | 只是"被限幅夹过"，**不是故障** |
| `u_l` 有值但电机不转 | 查 PWM/DIR 引脚（左 P10_2/P10_3、右 P05_2/P05_3） |

### 串口状态行（不用连上位机就能判）

```
[    12 s] err=0 online=1 en=0x000E rx_age=12ms safe=0x0000 int=1 tx=612 | L tgt=1.20 v=1.48 | R tgt=0.00 v=0.00 | cpr=1858/1858 | dL=12 fL=0 gL=0
```

| 字段 | 含义 | 正常值 |
|---|---|---|
| `err` | 0=OK 1=WiFi 失败 2=Socket 失败 | 0 |
| `online` | 最近收到过下行帧 | 1 |
| `en` | 使能位图 | 6 / 14（bit1 电机 + bit2 整体） |
| `safe` | 保护位图 | **0**（32 = 被限幅夹过，非故障）|
| `int` | WiFi 模块 INT（P02_4）电平 | ⚠ **这个字段采样时刻不对**（打印紧跟收包之后，模块必然忙）→ **恒为 0 是正常的**，别用它判断发送。看 `tx` |
| `tx` | 成功发出的遥测帧数 | 匀速 **+50/s** |
| `rx_age` | 距上次收到下行帧 | 0~100 ms 循环（**= 上位机 100 ms 心跳周期**；一直涨 = 上位机没在发）|
| **`dL`** | 本拍(5ms)计数增量 | = `cpr × v × 0.005`（1.4 rps → **12~14**） |
| **`fL`** | 真换向次数累计 | 每秒 **+0~1**；涨几十上百 ⇒ DIR 在抖 |
| **`gL`** | 读数毛刺丢弃次数累计 | 每秒 **+0~1** |

### 一个已验证的"健康基线"（1.4 rps 空载，可直接对照）

```
[  200 s] err=0 online=1 en=0x000E rx_age=25ms safe=0x0000 int=0 tx=9877 | L tgt=1.40 v=1.39 | cpr=1858/1858 | dL=13 fL=0 gL=0
```
- `v` 均值 **1.391** vs 目标 1.40 → 误差 **−0.7%**；σ = 0.075 rps（**5.4%**）
- 量化地板（窗口里 ±1 个计数）= 0.0269 rps = **1.9%** ⇒ 实测是地板的 2.8 倍，属正常
  （机械纹波 + 环路噪声放大），**不必再为它折腾滤波**

# 第 5 步 · 调参 / 滤波

## 5.0 ⚠⚠ 看波形之前先做两件事，否则一定在追鬼

### ① 把【自动量程】关掉

勾着自动量程时，Y 轴会被压到数据的 `[min, max]`。于是**±1 个计数的量化抖动会被放大成满屏的方波**，
看起来像"每拍计数极不稳定 / 有拾噪"。

**判据（10 秒）**：取消【自动量程】，把量程手动设成 `0 ~ 3×预期值` → 那条"方波"立刻变成几乎平的线。

成因：脉冲率（`cpr × v`）与采样率互质 ⇒ 每拍计数在 `n` 与 `n+1` 之间交替；
遥测又把它抽稀（200 Hz → 50 Hz）⇒ 出现**亚 Hz 的拍频**，正好像方波。**是假的。**

### ② 先算单拍分辨率：`1 / (cpr × Ts)` rps

| 参数 | 值 |
|---|---|
| `cpr` | 1858 |
| `Ts` | 5 ms |
| **1 个计数** | **0.108 rps / 拍** |

⇒ 目标 **0.4 rps 时一个计数就是 27%**（4 拍窗口后仍 6.7%），再叠上 49:27 齿轮的回差
⇒ **低速段的"噪声"大半是分辨率下限 + 机械，不是电气。**

> **结论：调参统一用 1.0~1.5 rps。** 1.24 rps 实测波形非常干净（`dlt_l` 全程 11~12，
> 理论值 `1858 × 1.24 × 0.005 = 11.52` ✓）。

## 5.1 再判「噪声是测出来的，还是真的」

**勾上 `dlt_l` / `dlt_r` 通道**（本拍 5 ms 里走了几个计数，单位 cnt）。

理论值 = `cpr × |v| × 0.005`。**0.4 rps 时只有 3.7 个计数** ⇒ 正常应该是 **3~5 的小整数**。

| `dlt_l` 的样子 | 结论 | 对策 |
|---|---|---|
| 孤立地蹦出 **±20 的尖刺**，中间仍是 3~5 | **拾噪（EMI）** | 见 5.3：治线 + 加大滤波窗口 |
| 一直平滑在 3~5，但 `v_l` 仍大幅摆 | **是真在摆**（机械 / 环路） | 见 5.2：调参 |
| 关使能、轮子静止时 `v_l` 不干净回 0 | **拾噪** | 见 5.3 |

> 顺带：`左轮计数` 一直在**单向漂**也是拾噪的特征（DIR 恒定时噪声只会往一个方向加）。

## 5.2 超调 / 振荡 —— 先吃斜坡，别急着砍增益

**2 个免费旋钮（本固件已内置，在线可调）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `限幅\|目标斜坡`（`slew`） | **20 rps/s** | 目标变化率上限。`0` = 关闭。0→1.5 rps 用 75 ms |
| `增益\|比例 k_v` | 0.164 | 降它 → 响应慢、过冲小 |
| `增益\|积分 k_z` | 2.32 | 只治静差，**不要用它治超调**（会越治越振） |

> 为什么先加斜坡：上位机拖滑条是**直接把值写进目标变量**的，等于把阶跃全额灌进环路。
> 工程里已经补了「目标斜坡 + 跳变超 `0.30 rps` 就清积分」，所以阶跃超调应该自动小很多 ——
> **先重烧固件看一眼，再决定要不要动增益。**

**顺序**：

```
① 重烧 19:49 那份 → slew 保持 20 → 看阶跃还冲不冲
② 还冲 → slew 降到 10（更缓）
③ 还振 → k_v 0.164 → 0.11
④ 有静差（稳定后 v 与 target 差 > 0.05）→ 再 k_z 往上加
```

## 5.3 拾噪怎么治

| 手段 | 效果 | 代价 |
|---|---|---|
| **`编码器\|滤波窗口` 4 → 8** | 噪声按 `1/√n` 降 ≈ 30% | 延迟 7.5 → 17.5 ms，**`k_v` 要相应降约 15%** |
| 编码器 A/B 与电机动力线**分开走线**、用双绞线、**就近共地** | 断掉共模干扰的来路 | 无 |
| ⚠ 硬件毛刺滤波 | **本平台没有** —— CYT4BB7 的 SDK 里 `cy_stc_tcpwm_counter_config_t` 无 `glitchFilter` 字段，全 SDK 也搜不到 `GLITCH_FILTER`，**别指望它** | —— |
| ⚠ RC 低通 | **不要加**：1.7 rps 时脉冲率已 3 kHz，低频 RC 会把信号一起杀掉 | —— |

**顺序**：先治线（免费且治本）→ 不行再加大窗口 → 再加窗口就要动 `k_v`。

## 5.4 ⭐ 判纹波/尖峰来源：三步实验（都不用重烧）

### 先记住两个换算（`cpr=1858, Ts=5ms`）

| 窗口 W | 窗口时长 | **1 个计数 = 多少 rps** | 等效延迟 |
|---|---|---|---|
| 4 | 20 ms | **0.0269** | 7.5 ms |
| 8 | 40 ms | 0.0135 | 17.5 ms |
| 10 | 50 ms | 0.0108 | 22.5 ms |

> ⚠ **"把采样周期 Ts 改成 10ms" 不是好做法**：`v` 的等效采样间隔是 `Ts × W`，
> 改 `Ts` 只等于改窗口（可由 `编码器|滤波窗口` 在线完成），却顺带把**控制周期**也拖慢
> ⇒ ZOH 延迟 2.5→5ms、`k_v` 要重算。**只改窗口。**

### 实验 1：看 PWM 本身抖不抖

勾上 **`u_l`**（或选「输出/前馈」预设，通道 `2,5,6,7`）—— 它就是每拍真正写进 PWM 的占空比。

| `u_l` 与 `v_l` 的关系 | 含义 |
|---|---|
| `u_l` 平滑、`v_l` 在抖 | 抖动**不是**控制器输出的 → 机械 / 量化 / 拾噪 |
| `u_l` 跟着 `v_l` 一起抖、且相位相反 | 环路在"追"测量噪声 → 闭环放大（下一实验能定量） |

### 实验 2 ⭐⭐ 恒定占空比（**定性的一步**）

**把 `增益|比例 k_v` 和 `增益|积分 k_z` 都拖到 0。** 此时 `u = u_ff(r)` 是**恒定值**，
控制器不再产生任何输出抖动（环路是开环的，安全）：

| 结果 | 结论 | 对策 |
|---|---|---|
| 纹波/尖峰**消失** | 是**环路自己产生的**（噪声→P→占空比→转速） | 降 `k_v`、加长窗口 |
| 纹波/尖峰**照旧** | 与控制器**无关** | 机械（49:27 齿轮回差）/ 量化 / 拾噪 → 见实验 3 |

### 实验 3：加长窗口（判"短时计数爆发"）

```
编码器|滤波窗口  4 → 8   （必要时 → 10）
同时把 k_v 降约 15%
```

| 结果 | 结论 |
|---|---|
| 尖峰高度**按比例缩小**（2 倍窗口 → 约一半） | **短时计数爆发**（EMI / PWM 串扰）→ 治线 |
| 尖峰**不缩** | 是真实的机械运动 → 别滤波，去查齿轮/负载 |

**反推尖峰需要多少额外边沿**（1 计数 = 0.0269 rps）：

| 尖峰高度 | 窗口里多出的计数 |
|---|---|
| +0.30 rps | 11 |
| +0.50 rps | 19 |
| +0.95 rps | **35** |

而 **17 kHz PWM 在 5 ms 里有 85 个周期 = 170 个边沿** —— 所以"一小段 PWM 串扰"
就足以给出这个量级。**尖峰高度除以 0.0269，就是必须解释的额外边沿数。**

> ⚠ 现成的毛刺门限 `ENC_DLT_GLITCH_MAX = 400` 只防"±2×当前计数"那种巨尖峰，
> **抓不住 35 个计数的爆发**。真要压它得上 `dlt` 中值滤波（滑动平均杀不掉爆发）。

### ⭐⭐ 一行算式判定"u 的抖动是不是 PWM 自己在抖"

**`Δu（占空比极差）= k_v × Δv`** —— 拿图上两个极差一比就知道：

```
实测: v 极差 0.40~0.62 = 0.220 rps;  u 极差 8.5%~12.2% = 3.70%
预测: k_v × Δv = 0.164 × 0.220 = 3.61%
=> 比值 0.98  ⇒ 完全吻合
```

- **比值 ≈ 1** ⇒ u 的抖动 100% 是 v 经 P 项"复印"的，**PWM 本身干净**，别再查它了；
- **比值 ≫ 1** ⇒ 才有额外的输出抖动（PWM 更新 / 中断抖动）→ 才需要查输出侧。

（`u_l` 就是每拍真正写进 PWM 的值，所以看它就等于"看 PWM 波形"。）

### 两个新参数在哪（改窗口 / 改斜坡）

在**左侧「参数（滑条实时下发 / 数字框精确输入）」面板滚到最底下**。
参数表按 ID 排序，新增的两项（ID 16/17）排在最后、各带自己的分组标题：

| 分组 | 参数 | 默认 | 说明 |
|---|---|---|---|
| `限幅` | **目标斜坡** (`slew`) | 20 rps/s | 目标**变化率上限**；`0` = 关闭 |
| `编码器` | **滤波窗口** (`enc_win`) | 4 | 1~16，**在线改窗口长度** |

⚠ 会看到**第二个「限幅」标题**（按 ID 排序所致），不是重复项。
⚠ **前提**：固件 ≥ 19:49 **且点过【刷新参数表】**。刷新后看不到这两行 = 固件不是那份。

### ⚠ 别把"饱和"当成"平静"

切断反馈（`k_v = k_z = 0`）后，`u` 应等于**前馈值** `r/6.46 + 0.033`（目标 0.6 → **12.6%**）。
**若 `u` 显示 ~50%（顶在限幅上），那不是"平静"而是"顶死"**
（目标 0.6 而 v=0 ⇒ 误差恒为 0.6 ⇒ 积分一路顶到限幅）。
**判据：`u_l` 是否等于前馈值。**
