# zjc_kart_cyt4bb7

智能车竞赛「**卡丁快跑**」组的预研工程 —— 在 **CYT4BB7**（英飞凌 TRAVEO™ T2G，双核 Cortex-M7）上跑
**左右双电机增量编码器闭环速度环**，并通过 **WiFi-SPI** 用 PC 上位机无线遥控、调参、看波形。

车端不再接受"开环占空比"指令：**上位机只下发目标转速（rps），闭环全部在车端跑。**

```
        ┌────────────────────┐   WiFi-SPI   ┌──────────────────────────┐
        │  KartHost (C#/Win) │ ◀──────────▶ │  CYT4BB7  CM7_0          │
        │  参数滑条 / 波形    │   固定协议    │  ├ spd_enc   测速        │
        └────────────────────┘              │  ├ spd_ctrl  速度环 LQI  │
                                            │  ├ spd_safety 五道保护门 │
                                            │  └ motor_drv 双路 PWM/DIR│
                                            └──────────────────────────┘
```

## 硬件接线

| 项 | 引脚 | 库里的名字 |
|---|---|---|
| 左电机 PWM / DIR | **P10_2 / P10_3** | `TCPWM_CH30_P10_2` / GPIO |
| 右电机 PWM / DIR | **P05_2 / P05_3** | `TCPWM_CH11_P05_2` / GPIO |
| 左编码器 脉冲 / 方向 | **P17_3 / P17_4** | `TC_CH58_ENCODER_CH1/2` |
| 右编码器 脉冲 / 方向 | **P19_2 / P19_3** | `TC_CH27_ENCODER_CH1/2` |
| 调试串口 | UART_0 @ **115200**（TX **P00_1** / RX **P00_0**）| — |

- 编码器引脚与库例程 `E2_01_encoder_dir_demo` 的「编码器1 / 编码器2」一致。
- ⚠ 右电机是 **CH11**（P05_2），不是 CH05 —— CH05 是 P02_2/P04_1，查枚举时最容易看错。
- 两路 PWM 同在 TCPWM0 GRP0，该组时钟分频共享 ⇒ **组内必须同频**（本工程都是 17 kHz）。

编码器为逐飞 1024 线 mini 增量式（**脉冲 + 方向**，不是正交），经电机轴 49 齿 → 27 齿增速：

> **每电机转 = 1024 × 49/27 = 1858 计数**（轮子与电机同轴，故也是每轮转计数）

## 被控对象（台架实测）

```
v = 6.46 · (u − 0.033)   [rps]        τ ≈ 24 ms      反馈等效延迟 ≈ 10 ms
```

- K / u0 来自 8 点稳态阶梯拟合（残差 ≤ 0.022 rps），另一组 4 点阶梯互证到 1%。
- ⚠ **这组数只对「驱动电机」（要装到卡丁后轮上那台）成立。**
  项目里还有一台「转向电机」（当舵机用）实测 **K ≈ 215**，相差 **33 倍**，
  **`k_v` / `k_z` / `inv_K` 一个数都不能互抄。**
- K 随负载变化：空载 K 最大（稳定性最差工况）。**落地带载后建议重测一组稳态点回填。**

## 控制律与增益

```
u = u_ff(r) + k_v·(r − v) + k_z·∫(r − v)dt
u_ff(r) = r/K + u0·sign(r)
```

| 参数 | 值 | 说明 |
|---|---|---|
| `k_v` | **0.164** | 相位裕度 60°、α=6 反解后整体砍半 |
| `k_z` | **2.32** | 同上 |
| `duty_limit` | 默认 **30%**，硬顶 60% | 该芯片上唯一的输出硬约束 |

台架闭环实测（MM32 参照平台，目标 0.5~1.5 rps）：**稳态误差中位 ±0.01 rps**。

## 保护（五道门，全过才允许出力）

1. 上位机说过话（上电以来至少收到一帧下行）
2. 使能位：`bit1` 电机 **且** `bit2` 总使能
3. 失联自停（超过 `lost_ms` 无下行 → 目标归零）
4. 主循环心跳（> 200 ms 没心跳 = 固件卡死 → 直接停机）
5. 占空比限幅（控制器夹一次，`motor_drv` 再夹一次）

门控不过时**输出严格 0 且清积分** —— 否则"被保护停住"期间误差一直累积，一放开门就是一次猛冲。
状态位图在遥测 `safety` 通道：`0x01` 没收到过下行 / `0x02` 未使能 / `0x04` 失联 /
`0x08` 无心跳 / `0x10` 配置非法 / `0x20` 本拍被限幅夹过。

## 编译与运行

**车端固件**（需要 IAR for ARM，本机在 `D:\IAR`）：

```bat
cd speed_loop_wifi_cyt4bb7
build.bat
```

或用 IAR 打开 `speed_loop_wifi\iar\cyt4bb7.eww`。
产物在 `speed_loop_wifi\iar\project_config\Debug_m7_0\Exe\`。
⚠ 双核 MCU **两个核都要烧**（CM7_0 是主程序，CM7_1 是空工程）。

**上位机**（需要 .NET 9 SDK）：

```sh
cd KartHost
dotnet build -c Release
bin/Release/net9.0-windows/KartHost.exe --selftest   # 自带 130 项自检
bin/Release/net9.0-windows/KartHost.exe              # 正常启动
```

上位机档案选 **「双电机速度环」**；参数滑条由车端参数表自动生成，遥测 20 通道。
网络配置（SSID / 密码 / PC 的 IP / 端口）在 `code/motor_link.h` 第一节，**换网络只改前四行**。

## 上电标定（顺序不能颠倒）

1. **电机方向** —— 给小正目标，确认电机朝「车前进」方向转；反了改 `minv_l` / `minv_r`。
2. **测速正负** —— 判据「正命令 ⇒ 该侧 v 为正」；反了改 `inv_l` / `inv_r`。
3. **每转计数** —— 清零 `pos_l`/`pos_r` → 单方向手转**电机轴**整 10 圈 → `cpr = pos 增量 / 10`。

三步都做成上位机滑条，**在线改、不用重烧**。
⚠ 第 2、3 步任一没做完就进闭环，结果一定是正反馈自激或量纲错。
详见 **`speed_loop_wifi_cyt4bb7/01-上电标定卡.md`**。

## 几个踩过的坑（留着免得再踩）

- **参数表要分批发**：连发 16 帧时模块"忙"会静默丢帧，上位机于是拿到一张**混血参数表**
  （一半车端名字、一半本地名字）→ **ID 错位** → 照着面板拖滑条会把**占空比限幅写成 0.02%**，
  现象是"上位机一切正常但电机不动"。改成每 5 ms 一帧、发不出去就重试同一条。
- **参数面板显示的不是车上的值**：`PARAM_META` 帧里只有 lo/hi/def/step。车端现在每发一项元数据
  **紧跟一帧该项的当前值**，刷新后才显示真值。
- **「脉冲 + 方向」编码器接进 x4 正交模式必然读数≈0**：单路信号在两个边沿上方向相反，正负相消。
- **换向那一拍要丢，但 DIR 必须去抖**：`if (dir != last_dir) delta = 0;` 遇上一次 1 拍毛刺会
  **连丢两拍** = 0.7 rps 的假凹陷，被环路当成真信号去"纠正"→ 波形上是一串周期性尖刺。
- 上位机的 exe 有多份副本（`bin/Release`、`bin/Debug`、`publish`），**改完源码记得全部重建**，
  否则会出现"改了代码但行为还是旧版"。
