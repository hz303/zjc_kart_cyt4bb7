| 右后轮 | PWM `P05_2`(CH11) / DIR `P05_3` | PWM `P05_1`(CH10) / DIR `P05_0` | **PWM `P10_2`(CH30) / DIR `P10_3`** |
| 转向 | PWM `P10_2`(CH30) / DIR `P10_3` | PWM `P10_2`(CH30) / DIR `P10_3` | **PWM `P05_0`(CH09) / DIR `P05_1`** |
| 预留 | — | PWM `P09_0`(CH24) / DIR `P09_1` | PWM `P05_2`(CH11) / DIR `P05_3` |

规律：`新M1 = 旧M4`、`新M2 = 旧M3`、`新M3 = 旧M2`、`新M4 = 旧M1`。

`P09_1` 同时是 `TCPWM_CH25_P09_1` 的候选脚 —— 本工程只把它当普通 GPIO 用，只要别处不再 `pwm_init(CH25...)` 就不打架。

## 4. 极性：三个开关，其中转向那个会烧东西

### 4.1 三个极性开关都在上位机滑条上（在线可改，不必重烧）

| 参数 | 作用 | 工程 7 实测值 | **工程 9 默认值** | 给反的后果 |
|---|---|---|---|---|
| `minv_l` | 左后轮整体取反 | 1 | **1** | 前进变后退 |
| `minv_r` | 右后轮整体取反 | 0 | **0** | 前进变后退 |
| `minv_s` | **转向电机整体取反** | 1 | **1** | ⚠⚠⚠ **位置环变正反馈 → 全速顶机械限位 → 堵转 → 烧 DRV8701** |

`minv_l=1 / minv_r=0` 的依据是**队友最新 `Motor.c` 的符号约定**：他对 `MOTOR_1`（左后轮）做 `duty = -duty`、`MOTOR_2`（右后轮）不取反，正好等价于这两个值。
`minv_s=1` 的依据是让整条链等效于队友 `SERVO_MOTOR_SIGN = -1`（推导见 `steer_ctrl.h` 的 `STEER_LOOP_SIGN` 注释）。

> **换引脚 ≠ 换电机接线。** 队友换通道时电机线怎么插的，只有他知道；上面三个默认值只能保证「符号约定和队友一致」，不能保证「物理方向一定对」。所以下面这一条必须做。

### 4.2 ⭐ 转向极性的台架验证（**上车第一件事，不能跳**）

```
1) 车架空（前轮离地），上位机连上，把「转向|内环使能」先留 0
2) 打开内环使能（steer_en = 1）→ 方向盘应当被"按"到中位附近并停住（目标自动取当前实测角）
3) 手推方向盘到 ±15 度左右，再给「转向|目标转角」一个很小的值（比如 +3 度）：
      · 方向盘朝"朝目标去"的方向走 → 极性正确，继续
      · 方向盘朝"背着目标跑"的方向走，或者一给就冲到底 → 立刻停手，
        把「转向|电机极性」(minv_s) 拖成 0 再试
4) 正反各走几次，确认没有单边冲撞，再落地上电跑
```

### 4.3 我在固件里加的两道主动保护（`steer_ctrl.c/h`）

队友在 `d9f5c4c` 里补了「反馈失效锁存」，工程 7 没有。工程 9 把两道都做了：

| 保护 | 判据 | 触发后 |
|---|---|---|
| ① 反馈失效 `STEER_FLT_ENC` | **前提用指令侧的 `abs(u)`**（反馈坏了就没有角度可读，不能拿角度当条件）：在出力（`abs(u) > 800`）状态下，绝对角读数连续 **200 ms** 落在全 0/全 1 特征值（`≤3` 或 `≥4092`） | 锁存，输出钉 0 |
| ② 顶死/反转 `STEER_FLT_SAT` | **本工程新增**：输出顶到 `u_max` 的 95% 以上（≈3325，对应 `err` 绝对值 ≥ 5.8 度），而误差绝对值还大于 3 度，**连续 600 ms** 不退 | 锁存，输出钉 0 |

②为什么能抓住「极性给反」：正确的 300 duty/度 环一旦饱和，说明误差有六度以上，以本车转速几十毫秒就能拉回来 —— **600 ms 一直饱和只可能是极性给反（正反馈自锁）或机械卡死**，两者都该停。
正常的「大角度阶跃」不会误报：判据看的是 **|err| 有没有缩小**（每个 100 ms 窗口至少缩 0.5°），
合法的 0→25° 阶跃误差一路在缩小 ⇒ 不触发。
> ⚠ 本节写于 2026-10-13，当时默认还有"40 度/秒的目标斜坡"；**§17 起斜坡默认已关**，
>   `err` 在阶跃那一拍就到位 —— 判据本身不变（看 |err| 有没有缩小），结论也不变（合法阶跃不误报）。

**复位方式**：两道都是锁存，唯一清除途径是「转向|内环使能」走一次 `0 → 1`。
**遥测可看**：`CH_STEER_STATUS` 的 bit1 = 反馈失效、bit2 = 顶死/反转（1 Hz 打印里是 `flt=0x0X`）。

**★ 中位死区：两个摇杆通道统一 ±8（原始计数，2026-10-13 按你的要求定）**

| 通道 | 之前的死区 | 现在 |
|---|---|---|
| CH2 油门 | `±8`（队友实测中位在 988/990/992 之间跳） | **不变**（本来就是 8，没动） |
| **CH1 方向盘** | **无死区**（只有归一化，抖动直接进环） | **`±8`** —— 死区内直接给 **0°** |

- 单位是**原始计数**：中位 992、单侧满量程 800 ⇒ **±8 ≈ 单侧的 1%**。
  换算：方向盘 ±0.27°（满 27°）、油门 ±0.02 rps（满杆默认 2 rps）。
- 死区是"**区内归零**"，不做重映射 ⇒ 刚出死区有 1% 的跳变，实车上感觉不到。
- 现场核对：勾通道 32 `rc_ch1`（原始值）/ 27 `rc_steer_deg`（指令角）——
  杆子在中位附近来回晃，`rc_steer_deg` 应当**稳定 0**、`rc_thr` 也是 0。
- 宏在哪：`remote_ctrl.h` 的 `RC_STEER_DEADBAND` / `RC_THR_DEADBAND`（两行，改一处即可）。

### 5.2 状态机（语义与队友一致，触发方式换成开关）

| 状态 | 触发 | 转向 | 后轮 | 本地接管档 |
|---|---|---|---|---|
| `OFF` (0) | 开关收回 / `rc_arm_en = 0` | 失能 | 失能、目标 0 | 0 |
| `STANDBY` (1) | 刚合闸 | 使能、目标 0（回中） | 使能、目标 0 | **1** |
| `ON` (2) | STANDBY 且油门回中（`abs(thr) <= 0.05`） | 使能、跟摇杆 | 使能、跟摇杆 | **1** |
| `FAILSAFE` (3) | 接收机报失控（`ST = 0`），**锁存** | 失能 | 使能、目标 0 | 0 |
| **`ESTOP` (4)** | **CH5 急停生效，锁存** | **强制失能** | **强制失能** | 0 |

三个刻意的设计：
- **合闸要油门回中才升到 ON**：防止合闸瞬间油门没归位就窜车。
- **FAILSAFE / ESTOP 都锁存**：失控过、急停过，都必须「先把开关收回去、再重新合闸」才允许再接管 —— 不让它自动恢复。
- ⭐⭐ **急停是"全局硬停机"，与谁在开车无关**：`spd_safety_set_estop()` + `steer_ctrl_set_estop()`
  把两个环**无条件**钉 0 —— **即使此刻是 WiFi 上位机在开车，拨一下 CH5 也能停**。
  它落成保护层的 `SAFE_BIT_ESTOP (0x80)`，**和心跳门、限幅门一样不可被本地接管替换**；
  转向侧走的是同一个"门控不通过"唯一收口，不会出现"这里也写 0、那里也写 0"互相打架。
  （为什么这么做：用户明确要求「至少要有一种手段能够控制住车辆，防止发生某些意外」。）

### 5.3 与队友的三处结构差别（需要你确认，见 §10）

| # | 队友 | 工程 9 | 为什么 |
|---|---|---|---|
| 1 | 进 IPS200 菜单页 + 按确认键接管 | **CH6 二值开关接管**（CH5 让给急停） | 工程 7 **没有屏幕、没有按键**（全程走上位机）。想换通道只改 `RC_CH_ARM` 一行 |

## 6. 遥控如何做到「不依赖 WiFi」

### 6.1 问题在哪

工程 7 的保护层 `spd_safety` 有**五道门**，其中**前三道是「上位机在场」**：

| # | 门 | 位 |
|---|---|---|
| 1 | 上电以来至少收到过一帧下行 | `SAFE_BIT_NEVER_RX` |
| 2 | 使能位图 bit1(电机) + bit2(总使能) 都置位 | `SAFE_BIT_NOT_EN` |
| 3 | 链路不超时 | `SAFE_BIT_LOST` |
| 4 | 主循环心跳（200 ms） | `SAFE_BIT_NO_HB` |
| 5 | 占空比限幅 | `SAFE_BIT_OVER_LIM` |

**SPI 都没插的时候，前五道里前三道必然不过 → 电机永久锁死，而且一个错都不报。** 这正好违反你要求的「即便小车没连上 WiFi，仍然可以通过遥控器完全操控」。

### 6.2 解法：本地接管（照工程 8 已验证的做法搬过来）

```
void spd_safety_set_local(uint8 on);     /* on=1 -> 跳过 1)/2)/3)，改亮 SAFE_BIT_LOCAL(信息位，不阻塞) */
```

- 遥控进 `ON` / `STANDBY` → `set_local(1)`
- 遥控退 `OFF` / `FAILSAFE` → `set_local(0)`，完整五道门原样恢复
- ⚠⚠ **第 4) 心跳门与第 5) 限幅门永远生效，不参与替换。**
  本地接管换掉的是「上位机在场」，**不是「MCU 还活着」**。主循环一卡死（>200 ms 无心跳）照样立刻停机，否则 5 ms 中断里的控制器会在主循环死掉之后继续给占空比 —— 那才是真的失控。
  同理限幅也不许绕：遥控全油门也必须过 `duty_limit`。

### 6.3 由此推出的一条硬约束（**改代码时别踩**）

> **谁能把后轮闭环转起来，谁就必须每圈喂 `spd_safety_heartbeat()`。**

工程 9 的遥控是挂在**主循环**里的两个函数（`remote_ctrl_update()` + `remote_ctrl_apply()`），主循环每圈本来就喂心跳，所以天然满足。
**千万不要**把遥控做成 `while(1)` 页面 —— 那样主循环心跳就断了，保护层会在 200 ms 后把电机全部钉 0。
（这正是队友那份工程 `Motor_Crtl.h` 里专门写了一大段警告的坑：他的页面循环里必须手动调 `Motor_Crtl_HB_Feed()`。）

### 13.2 上位机拖 `target_l` 没用、车端 `target_l` 恒 0（车端 bug，**必须重烧 CM7_0**）

现象：上位机把"左轮转速"拖到 **2.85 rps**，波形图例与数值框里 `target_l` 始终 **0**。

**根因**在 `remote_ctrl.c` 的 `remote_ctrl_apply()`：旧代码在 **STANDBY / ESTOP / FAILSAFE / OFF**
四个分支里**每一拍**都写

```
spd_target_l = 0;  spd_target_r = 0;  steer.target_delta = 0;  steer_en_cmd = 0;
```

而接收机没插时 `RC_Online` 恒 0 ⇒ 状态机恒为 `FAILSAFE` ⇒ **遥控模块以 5 ms 周期把上位机刚写进去的目标清成 0**。
参数 `target_l` / `target_r` / `steer_tgt` 是**按地址直接下发到这三个变量**的（`motor_link.h` 参数表），
所以这三个滑条在该状态下**全部失效，并且不报任何错**。

**修法**（语义写死在 `remote_ctrl.c` 顶部注释里）：

| 状态 | 三个目标量（`spd_target_l/r`、`steer.target_delta`） |
|---|---|
| `ON` —— 遥控真的在开车 | **每拍写**（全工程唯一一处） |
| 进 `STANDBY` 那一拍 / 从 `ON`·`STANDBY` **退出**那一拍 | **写 0 一次**：停住 + 方向盘回中（管住"摇杆还推着但接收机突然没了"） |
| 其余任何时刻（含 `FAILSAFE` / `OFF` / `ESTOP`） | **一个字都不写** —— 控制权在上位机 |

⇒ 一句话：**"遥控没在开车" ≠ "车必须停"**。要停有急停门（`spd_safety_set_estop()` 硬钉两环输出）
和占空比限幅门，不该靠"霸占目标量"来实现。

1. 上位机连上，勾选通道 **26 `rc_eng`** 看那格数字：`0=OFF / 1=待命 / 2=接管 / 3=失控`。

## 14. ★ 2026-10-13 现场第三问：转向「给指令，但是不动」—— 是保护锁存，不是指令没到

### 14.1 一眼判据：看 `steer_status`

| `steer_status` | 含义 | 车端行为 |
|---|---|---|
| **1** | 只有 bit0（编码器自检通过），无故障 | 正常 |
| **3** | bit1 = fault `0x01` **反馈失效** | 输出钉 0 |
| **5** | bit2 = fault `0x02` **顶死 / 无进展** | ★ **只报警、不钉输出**（同日已改，见 §15）|
| **7** | 两个都锁存 | 输出钉 0 |
| **0** | 连自检都没过（编码器没接好/读不到） | 输出钉 0 |

实测现场：`steer_tgt 10deg`（**指令确实到了车端**）+ `steer_u 0duty` + `steer_status 5`
⇒ **不是"上位机没发出去"，是车端保护把输出按住了。**

### 14.2 为什么会锁存（判据回顾）

输出 ≥ `u_max` 的 95% **且** |err| ≥ 3°，**连续 600 ms 里 |err| 连 0.5° 都不缩小** ⇒ 锁存。
本轮参数 Kp = 300 / u0 = 1600 / u_max = 3500 ⇒ 饱和门槛 |err| ≈ (3500 − 1600) / 300 ≈ **6.4°**；
目标斜坡 40°/s ⇒ err 爬到 6.4° 约需 160 ms，再累计 600 ms ⇒ **约 0.8 s 后锁存**。

> ⚠ **本节是 2026-10-13 当时的状态记录**，两个前提后来都变了：
>   **目标斜坡默认已关**（§17）、**`u_max` 已提到 9000**（§18）⇒
>   饱和门槛变成 `|err| ≈ 24.7°`、且阶跃那一拍 `err` 就到位。
>   判据本身不变（看 `|err|` 有没有缩小），但**"约 0.8 s 后锁存"这个数只对当时有效，别再引用**。

⇒ 锁存只说明**"出力了、但角度不跟"**，它分不开下面三种根因（这是刻意的取舍：宁可三种都停掉，
也不要让极性问题把 DRV8701 烧了）：

1. 极性给反（误差越出力越大）；
2. 机械卡死 / 顶住；
3. **根本不出力**（供电 / 接线 / 驱动器）。

### 14.3 复位（**唯一途径** —— 只对 bit1「反馈失效」这种锁存故障成立；bit2 只是告警，不需要复位）

把参数「转向|内环使能」`steer_en` 关到 **0** 再打开 **1** —— 车端 `steer_ctrl_set_angle_enable()`
的 0→1 上升沿是唯一复位点。

⚠⚠ **复位那一拍车端会拿"当时的实测角"覆写 `steer.target_delta`**（防超调）。于是滑条上写着 10.5°、
车上其实还是 −1.56° —— 现场表现就是"我按提示关了再开，还是不动"。
**上位机已改成：打开内环使能时自动补发一次 `steer_tgt`**（`MainForm.OnParamChanged`），
并把故障位翻译成人话打进日志、把那一格标红（`MainForm.CheckSteerFault`）。

### 14.4 复位后那 600~800 ms 是"免费窗口"—— 用它定位根因

复位后立刻给一个 5~10° 的目标，盯 `steer_u` 与 `steer_delta`：

| 现象 | 结论 | 对策 |
|---|---|---|
| `steer_u` 冲到 3325+，`steer_delta` **朝目标去** | 正常（上次是偶发，比如轮子被手压住） | 不用动 |
| `steer_delta` **背着目标跑**（误差变大、很快又锁存） | **极性反** | 先把「转向\|电机极性」`minv_s` 翻一下（0↔1）；若翻它没用，是编码器符号（`steer_abs`）反了 |
| `steer_u` 有值（≥3325）而 `steer_delta` **纹丝不动** | **执行器根本没出力** | 按下面顺序查 |

**"根本不出力"的查法（顺序别跳）**：

1. **带载量供电**：转向驱动器的 VM 在"一动就塌"的时候掉到多少（空载量不算数）；
2. **接线**：工程 9 的转向通道**换了引脚** —— `P05_0 (CH09)` = PWM、`P05_1` = DIR。
   插错排针、或还插在旧位置（`P10_2 / P10_3`）都会"看着接上了、其实没接对"；
3. **驱动器**：DRV8701 的使能/睡眠脚、或直接换一块模块试；
4. 最后才怀疑固件。

⚠ 台架验证（车架空）请用**小角度 ±3°**：这样 `Kp·err + u0` 远到不了饱和门槛，保护不会插手。

## 15. ★ 2026-10-13 四次修订：顶死保护从「锁存失能」改成「只告警」

现场判定（你的原话）：**±27 是保护限位、机械极限还有余量，所以满转到 27 不会堵转、不会烧**。
而这条保护在"打到行程末端"时本来就容易触发 —— 连杆到头那一段机械增益差又涩、方向盘爬得慢，
`|err|` 每 100 ms 缩不到 0.5° 就被判成"无进展" ⇒ **正常打到最大角反而被失能**，比不保护还碍事。

改动（`steer_ctrl.c/h`，双核 **0 错 0 警**）：

| | 之前 | 现在 |
|---|---|---|
| 反馈失效 `STEER_FLT_ENC` | 锁存 + 输出钉 0 | **不变**（队友的方案，保留） |
| 顶死 / 无进展 `STEER_FLT_SAT` | 锁存 + 输出钉 0 | ★ **只置告警位，不碰输出**；条件消失后自清（粘滞 `STEER_SAT_WARN_HOLD_MS` = 2 s） |
| 记账条件 | 饱和 + 0.6 s 无进展 | 同上，但**已压在生效限位 ±1° 以内时不计账**（那一段机械上本来就到头了） |

配套：

- `steer_ctrl_fault()` 仍返回 `bit0 = 锁存故障 / bit1 = 顶死告警`，**遥测 `steer_status` 的位序一个都没动**
  （上位机的解读照旧按 `0x01 / 0x02` 走）；
- 上位机 `SteerFaultText()` 跟着改口径：bit1 = "锁存故障，输出已钉 0"（给复位步骤），
  bit2 = "**只是告警，车端没有停输出**"；告警时还会把 **目标 / 实测 / 输出三个数**一起打进日志
  （下次不用再猜"到底是谁没跟"）；
- 上位机自检里有一条专门钉住"bit2 不许写成锁存"：`SteerFaultText(5)` 必须含"告警"、不含"钉 0"。

⚠ **保留告警的理由**：它正是今天定位问题的第一手线索（遥测 `steer_status` bit2）。
⚠ 从此"极性给反会烧 DRV8701"这件事**只靠台架验证兜**（§4.2）—— 上车前那一步仍然不能跳。
⚠ 若这条告警以后变成误报噪声（比如转角标定不准），把它调钝即可：`STEER_SAT_ERR_DEG` 调大、
`STEER_SAT_WARN_HOLD_MS` 调小 —— **它不控制任何动作**。

## 17. ★ 2026-10-14 六次修订：删掉转向的目标斜坡（照队友实测）

**来源**：队友 `YINGYYUN/Karting-Project`，commit `4ce6c93`
「feat:2026.10.14.22:03:删除了舵机的目标斜坡」。他的实测结论（微信原话）：
> 「舵机的目标速度斜坡可以直接删了」「直接删没有发现震荡」

### 17.1 他的改动（`project/code/Servo_Crtl.c/h`）

| 项 | 改前 | 改后 |
|---|---|---|
| 目标处理 | 软限位夹紧 → **再按 120 度/秒限速率** | **只做软限位夹紧**，速率限制整段删除 |
| 实际施加目标 | 只存在内部静态量 `servo_target_applied` | 新增**对外变量** `Servo_Target_Applied_Deg`，并在**门控之前**赋值 ⇒ 与是否使能无关 |
| 调试口/串口输出 | 发"屏幕上的 raw" | 明确改发 `Servo_Target_Applied_Deg`（注释写着"**不要用 `Servo_Target_Deg`**"） |
| `SERVO_U0_DEFAULT` | 1300 | **1600** |
| `SERVO_U_MAX` | 6000 | **7500** |

他的原话理由（写在代码注释里）：
> 目标阶跃时不再限速率：误差一次性给足，`Kp·err` 直接顶到输出限幅 → 满 PWM、最快到位。
> 代价是没有减速过程，到位附近靠背隙/摩擦自然停住。

### 17.2 为什么这条对本工程同样成立（结构一模一样）

本工程的控制律就是**照他抄的**（纯 P + 静摩擦前馈，见 `steer_ctrl.h` 顶部）。斜坡在这里是多余的：

- **没有积分器** ⇒ 阶跃不需要"防积分裹死"，那是 PI 才有的问题；
- 误差已被 **±27° 软限位**卡住 ⇒ 最大 `Kp·err = 300×27 = 8100`，本来就该顶到 `u_max` 求最快；
- 留着斜坡**只剩纯滞后**。⚠ 我们这条还是 **40 度/秒**（他 120），5 ms 拍 ⇒ 0.2 度/拍
  ⇒ 同样 0→27° 的阶跃，他 225 ms 走完，**我们要 675 ms** —— 这是"角度环响应延迟"的一大半。

### 17.3 本工程落地了什么

| # | 改动 | 位置 |

| 1 | `STEER_SLEW_DEG_S_DEFAULT` **40 → 0**（关）；`steer_slew` 参数默认值同步改 0 | `code/steer_ctrl.h`、`code/motor_link.h` ID25、上位机 `Defaults.cs` |

## 18. ★ 2026-10-15：转向输出限幅 `u_max` 3500 → **9000**（用户拍板）

### 18.1 改了什么

| 处 | 改前 | 改后 |
|---|---|---|
| `steer_ctrl.h` 的 `STEER_U_MAX_DEFAULT` | 3500（35%） | **9000（90%）** |
| `motor_link.h` ID22 `steer_umax` 默认值 | 3500 | **9000** |
| 上位机 `Defaults.cs` 同名参数默认值 / `Simulator.cs` 兜底 | 3500 | **9000** |

（`Motor_Set` 刻度两边都是 `±10000 = ±100%`。）

### 18.2 ⚠⚠ 真正的变化不是"力气大一点"，而是**饱和门槛**

`u = Kp·err + u0·sign(err)`，`Kp = 300`、`u0 = 1600` ⇒ **饱和（输出顶到 `u_max`）所需的 `|err|`**：

| `u_max` | 饱和门槛 `(u_max − u0)/Kp` | 实际效果 |
|---|---|---|
| 3500（旧） | **≈ 6.3°** | 误差一过 6.3°，输出就**恒定 35%** —— 大角度阶跃**一半以上的路程被限幅压着** |
| **9000（新）** | **≈ 24.7°** | 几乎**全行程都在线性区**，只有顶到 ±27° 附近才饱和 |

⇒ 到位速度的"决定权"从**限幅**交回给 **`Kp` 本身**（`u = 300·err`：err = 12° 就是 52% duty）。
⇒ 一句话：**从"限速巡航"变成"全程按误差比例给力"** —— 前段明显更快，也明显更冲。

### 18.3 ⚠ 副作用（两条，都有代价）

1. **电流 / 发热**：90% duty 是有刷电机 + DRV8701 能给的**极限档**。长时间堵转（机械卡死）会烫。
   - 保证只剩两道：**"反馈失效"锁存钉输出**（`STEER_FLT_ENC`）、**越限保护**（实测超软限位且误差仍
     指向限位 ⇒ `err` 置 0）。**"顶死/无进展"只告警、不停输出**（见 §15），所以它不兜这条。
   - 真担心就按 §4.2 台架先跑 5 分钟连续满力，摸驱动温度。
2. **`STEER_SAT_*` 告警变钝**：它的"顶到限幅"判据是**相对 `u_max` 的 95%**（= 8550）
   ⇒ 需要 `|err| ≥ 23.2°`，比 3500 时代（`|err| ≥ 5.8°`）**难触发得多**。
   - 抓"极性给反 / 机械卡死"**仍然够用**（那两种的误差会一路涨到软限位 27°，必然越过 23.2°）；
   - 但它**不再是"环在满力顶"的灵敏指示器**。要它灵敏，就把 `STEER_SAT_OUT_RATIO` 换成
     **绝对 duty 门槛**（例：`steer.output_duty >= 4000` 就算"在出力顶"），
     别只盯 `0.95` 这个相对值 —— **它随 `u_max` 一起漂，`u_max` 一动它就失效**。

### 18.4 怎么撤

- **不改默认值**：上位机 ID22 `steer_umax` 直接拖回 3500/6000 —— 在线生效，不用重烧；
- **改默认值**：三处一起改（`steer_ctrl.h` 宏 + `motor_link.h` ID22 + 上位机 `Defaults.cs`），
  改完重编双核 + 重发上位机。

### 18.5 验证

- 车端双核 **0 error / 0 warning**；上位机 **388 项自检 0 失败**（+3：钉 9000 默认值、量程容得下、
  `u0` 仍远小于 `u_max`）。
- ⚠ **上车验证顺序**：① 台架（前轮离地）先给 0→5→10→20→27 的阶跃，看 `steer_u` 波形是不是
  **随误差线性上升**（旧版会一路平在 35%）；② 摸驱动温度；③ 落地下地再跑一遍；
  ④ 对拍 `steer_slew=0 / u_max=3500` 与 `u_max=9000` 两组曲线。
