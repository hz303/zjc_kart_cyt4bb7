# KartHost · 卡丁快跑上位机

替代车上那块 2.4 寸屏菜单的**远程无线调试上位机**。车通过 SPI 转 WiFi 模块（逐飞 `zf_device_wifi_spi`）以 TCP/UDP 上传遥测，本程序负责波形显示、参数下发、使能控制。

设计依据见 `../卡丁快跑-上位机设计方案.md`（协议与架构那一份）。

---

## 一、先跑起来（不需要任何硬件）

```bat
:: 方式 1：直接双击
publish\KartHost.exe

:: 方式 2：源码运行
dotnet run
```

打开后：

1. 点顶部 **「模拟车端」** —— 它在 `127.0.0.1:8086` 起一个假车端
2. 点 **「连接」** —— IP 会自动填成 `127.0.0.1`
3. 波形立刻开始动；拖参数滑条，日志里能看到「参数写入：xxx ← yyy」

**这一步很重要**：先在没有硬件的情况下把界面、参数表、波形都调顺，等车做出来只管接链路。

```bat
:: 自检（协议 / 帧同步 / 端到端链路 / 七个档案 / 界面构建 / 二维轨迹 / 路表链路，共 388 项）
publish\KartHost.exe --selftest selftest.txt
```

### 5 / 6 号档案（2026-10-13 新增，2026-10-14 加「增益回读」）

| 档案 | 通道 | 说明 |
|---|---|---|
| 卡丁·遥控 | 39 | 0~25 = 「转向闭环」**一字不差**；26~36 = 遥控组（急停 / 使能 / 指令 / 原始通道值 / 收帧数）；**37~38 = `k_v` / `k_z` 增益回读** |
| 标定·精简 | 18 | 速度环左(目标/实际/PWM) + 速度环右 + 舵机角度环(目标/实际/PWM) + 状态 + 预留 + **16/17 = `k_v` / `k_z` 增益回读** |

> ⚠ **「增益回读」是什么**：以前 CSV 里没有"车上真正跑的是多少增益"这一列，
> 只能拿文件名当参数 —— 而文件名可能是错的。两个地方会**悄悄**改掉你设的值、且都不报错：
> ① 滑条 `Snap()` 按步长吸附（`k_v` 0.005 ⇒ 0.164 被吸成 **0.165**）；
> ② 车端旧固件在 `SET_PARAM` 后还按步长取整一次（已修）。
> 现在控制器本拍真正用的值原样发回来，**CSV 自带这两列，再也不用猜**。
> 「增益」分图预设 + 默认勾选，一开界面波形里就有。

> ⚠⚠ **但"这两列是增益"有个前提：帧里的通道数要和当前档案一致**。
> 2026-10-14 实测踩坑：车端发**全量 39**、本机档案停在**「标定·精简」18** ⇒
> **通道名整体错位 21 个下标**（两种布局前 6 列恰好同名同义，所以前面看着一切正常）。
> 错位正好落在增益上：图例里的 `k_v` 其实是 ch16 = **`online`**（恒 1）、
> `k_z` 其实是 ch17 = **`rx_age`**（毫秒计数器，被 100 ms 心跳清零 ⇒ 一条锯齿）。
> ⇒ 现在**波形上会压一条红色警示条**，写明"N 通道 ≠ M 通道 —— 通道名整体错位"，
> 并在唯一能确定档案时给出 **「点此切到「卡丁·遥控」」**，**点一下自动切**
> （连接中也允许切，切完缓冲自动清零）。
> 出图：`KartHost.exe --shot-form warn.png calib 39`（第 4 个参数 = 假装帧里有 39 个通道）。

### 4 号档案「惯导+路表」（2026-10-07 新增）

车端 = `A_zjc_project/8.ins_route_cyt4bb7`（C 车：CYT4BB7 + IMU963RA + 正交编码器 + 舵机 + WiFi-SPI）。

| 通道 | 内容 |
|---|---|
| 0~19 | 与「双电机速度环」**完全一致**（速度环 + 编码器 + 链路 + 保护） |
| 20~22 | **舵机**：归一化舵量 / duty（2160 右 ~ 2420 中 ~ 2660 左）/ 使能 |
| 23~25 | 横滚 / 俯仰 / 陀螺 Z（°/s） |
| 26~29 | **位姿 X(m) / Y(m) / 累积航向(°) / 累计里程(m)** |
| 30 | 状态位图：bit0 就绪 / bit1 磁已标定 / bit2 静止 / bit3 打滑 / bit4 路表录制中 / bit5 路表满 / bit6 IMU 失联 / bit7 告警 |
| 31 | 采样序号（应匀速增长；用来统计丢帧） |

> ⚠ **20~25 与「转向闭环」档案的 20~25 语义不同**（那边是"转向直流电机 + 绝对编码器"的位置环，
> 这边是舵机 + 惯导）。**两个档案 20 号以后不要混着解读**；参数表也必须整份替换，
> 因为车端 `MOTOR_PARAM_TABLE` 在 ID 18 之后是两套不同的东西。

> ⚠ **三个"边沿命令"是滑条，不是按钮**：`ins_route`（0→1 开始录、1→0 停止）、
> `ins_zero`（0→1 归零一次）、`ins_magcal`（0→1 开始、1→0 结算）。
> **拖到 1 之后要拖回 0** 才能再次触发 —— 与车端"只在边沿那一拍动手"的实现对应。

> ⚠ 标定顺序：电机方向 → 计数正负 → **每转计数 cpr（默认 1024；CYT4BB7 的正交是 X1 倍频，
> MM32 那边才是 X4=4096）** → **比例尺 `ins_mpm`（默认 1.0 是占位假设「1 rps = 1 m/s」，
> 等价轮周长 1 m；小模型车真实值约 0.19~0.25，实测后必改）** → yaw 符号（编译期）→ 磁标定。

> 模拟车端**也支持这个档案**：它的位姿不是随机数糊出来的，而是把左右轮实测转速按
> `v=(v_l+v_r)/2×米每转`、`ω=(v_r−v_l)/轮距` 积分出来的（和车端 `ins_odom.c` 同一套公式）。
> 所以拖 `target_l/target_r` 滑条就能看到车真的走、真的转；差速一转，yaw 就跟着变。

## 二·二、实时二维轨迹面板（2026-10-08 新增）

移植自 `A_zjc_project/3.1imu_trails_mode_pc` 的 `Ui/BoardView.cs`，挂在波形区下方（分隔条可拖）。

**它画什么**：网格 + 比例尺 + 轨迹（按时间着色：**起点冷色 → 末端暖色**）+ 车体（圆角矩形 + 车头三角 + 指向箭头）
+ 旋转方向弧（左转绿 / 右转橙）+ 速度矢量 + 右上角罗盘 + 左上角 HUD（位姿/航向/角速度/里程/点数/状态位）+ 左下角图例。

**数据来源**：只读 `ChannelStore` 的 26/27/28/29/30（`ins_x / ins_y / ins_yaw / ins_dist / ins_flags`），
30 FPS 由主界面定时器驱动（与波形同频、共用一次快照）。**只在「惯导+路表」档案下显示**
—— 别的档案里 26/27 是毫不相干的通道，不挡住就会画出一条乱轨迹而且不报错。

**坐标约定（★ 与车端 `ins_odom.c` 一模一样，移植时没做任何旋转/镜像）**：

| | 车端 | 上位机 |
|---|---|---|
| 位移 | `dx = -sin(yaw)·ds`、`dy = +cos(yaw)·ds` | 同式 |
| 显示 | — | **+x = 屏幕右，+y = 屏幕上（y 轴翻转）** |
| 含义 | yaw 从正北起、俯视**逆时针为正** | yaw = 0/90/180/270 → 车头朝 **上/左/下/右** |

⇒ 车体用 `TranslateTransform(位置) + RotateTransform(-yaw)`，变换后局部"上"就是车头。
这条约定被 `SelfTest.TestBoardView()` 用**基准数**钉住了（`Heading(0°)=(0,+1)`、`Heading(90°)=(-1,0)`…）——
因为**符号一旦反了，画面"看起来也是一条轨迹"**，只有拿数才抓得出。

**交互**：滚轮以光标为锚缩放 / 左键拖动平移 / 双击或按 `F` 自适应 / `+`·`-` 缩放。
工具条三个按钮：

| 按钮 | 行为 |
|---|---|
| 自动适应 | 包围盒居中 + 缩放到刚好装下（四周留 55 逻辑像素内边距） |
| 清空轨迹 | 只清本地轨迹缓冲，**不影响波形、也不动车端位姿** |
| 车端归零 | 发 `ins_zero` 边沿（车端 x/y/航向/里程归零）**并**同步清空本地轨迹与基准 |

> ⚠ 「车端归零」必须两边一起做，而且**不能 1、0 连发两帧**：车端是按 0→1 **边沿**触发的，
> 两帧挤在同一圈主循环里会只看到最终值 0，边沿就丢了。所以这里隔 200 ms 再把值拖回 0。

**两个已知的"看着像 bug 其实不是"**：

| 现象 | 原因 |
|---|---|
| 轨迹末端差一点点没接到车 | 按 **2 cm 距离阈值**抽稀，尾部不足 2 cm 的那一截不记点。末端离车心 ≤2 cm，被车体（≥26 px）盖住，看不出来 |
| 直行 1 m 只记了约 51 个点 | 2 cm 一条 ⇒ 100/2 = 50 个间隔（+ 起点）。这是刻意的：静止时不涨点，否则噪声会把"自动适应"越撑越大、画面一直抖 |

**自检**（`TestBoardView()`，12 项）：航向约定 4 项 + 屏幕映射 3 项 + 抽稀/清空 3 项 + AutoFit 2 项
（AutoFit 的比例与中心都是按包围盒**解析算出来**再比对的，不是"看着差不多"）。

## 三、和真车对接：MCU 侧要做的事

上位机这边已经写好了。车端需要按协议实现四件事：

### 1. 遥测帧（发送，最高频）

```c
// 载荷：SEQ(2) + TIMESTAMP(4) + VALID_MASK(2) + COUNT(2) + float32[COUNT]
uint16 build_telemetry (uint8 *buf)          // 返回整帧长度
{
    uint16 pl = 10 + cnt * 4;
    uint16 n = 0;
    buf[n++] = 0xA5;  buf[n++] = 0x5A;                 // MAGIC
    buf[n++] = 0x01;                                   // TYPE = TELEMETRY
    n = put_u16(buf, n, pl);                           // LEN
    n = put_u16(buf, n, tx_seq++);                     // SEQ
    n = put_u32(buf, n, systick_ms);                   // TIMESTAMP
    n = put_u16(buf, n, valid_mask);                   // VALID_MASK
    n = put_u16(buf, n, cnt);                          // COUNT
    memcpy(buf + n, ch, cnt * 4);  n += cnt * 4;       // ★ 直接拷内存，不要 sprintf
    n = put_u16(buf, n, crc16_modbus(buf + 2, 3 + pl));
    buf[n++] = 0x00; buf[n++] = 0x00; buf[n++] = 0x80; buf[n++] = 0x7F;  // TAIL
    return n;
}
```

**三条纪律**（详见设计方案 §1.2 / §2.3 / §7）：

1. **不要 `sprintf`** —— 直接把 `float` 的内存拷进缓冲，零格式化开销；
2. **只在主循环里发**，绝不在中断里发（`wifi_spi` 内部有非原子的 mutex）；
3. **发送前先判 `INT` 引脚**，模块忙就跳过本帧；并把 `zf_device_wifi_spi.c` 里的
   `OTHER_TIME_OUT` 从 `1000` 改到 `1~2`（否则最坏阻塞 **1 秒**）。

### 2. 命令帧（接收）

下行固定 15 字节（`5A A5 | 01 | 08 00 | CMD | ID | VALUE(4) | TOKEN(2) | CRC(2)`）。
车端解析时**CRC 不过只前移 1 字节**，不要跳过整帧。

必须实现的命令：

| CMD | 含义 | 车端动作 |
|---|---|---|
| `0x01` | PING | 回 ACK |
| `0x03` | SET_PARAM | **先按参数表的 lo/hi 钳位**，再写入，然后回 `PARAM_VALUE`（上位机据此确认） |
| `0x04` | SET_ENABLE | 按位解释；**bit2（整体）为 0 时，其余位一律不生效** |
| `0x05` / `0x06` | 存/读 Flash | 存参数 / 恢复默认 |
| `0x07` | GET_TABLE | **逐条回 `PARAM_META` 帧**（这是上位机自动生成界面的来源） |

### 3. 参数表（X-Macro，一份定义多处展开）

```c
#define PARAM_TABLE(X)                                                  \
    X(0, steer_kp,    "转向Kp",   0.0f, 100.0f, 1.50f, "-",  0.05f)     \
    X(1, steer_ki,    "转向Ki",   0.0f,  10.0f, 0.02f, "-",  0.005f)    \
    /* 加参数 = 加一行，上位机不用改代码、不用重编译 */
```

`PARAM_META` 载荷 73 字节：
`ID(1) + LO(4) + HI(4) + DEF(4) + STEP(4) + UNIT(8) + NAME(16) + LABEL(32)`

其中 `LABEL` 字段填 **`组名|中文标签`**（例如 `转向环|转向 Kp`），上位机按 `|` 拆分成折叠分组。

### 4. 失联保护（车端责任）

**车端必须在 500 ms 收不到任何下行帧时自行停机**，不要依赖上位机。
拔掉 WiFi 之后车还在跑，是这类远程调试最危险的事故模式。

## 四、协议速查

**统一帧头结构**（上下行同构，只是 MAGIC 反序）：

| 上行（车→PC） | 下行（PC→车） |
|---|---|
| `A5 5A` + `TYPE(1)` + `LEN(2)` + `PAYLOAD` + `CRC16(2)` + `TAIL(4)` | `5A A5` + `TYPE(1)` + `LEN(2)` + `PAYLOAD` + `CRC16(2)` |
| 总长 = **11 + LEN** | 总长 = **7 + LEN**，LEN 固定 8 |

| TYPE | 名称 | 载荷 |
|---|---|---|
| `0x01` | TELEMETRY | `SEQ(2)+TS(4)+MASK(2)+COUNT(2)+float32×N` |
| `0x02` | PARAM_META | 见上，73 字节 |
| `0x03` | PARAM_VALUE | `ID(1)+float32` |
| `0x04` / `0x05` | ACK / NAK | `TOKEN(2)+CMD(1)+…` |
| `0x06` | EVENT | `LEVEL(1)+文本` |

- **CRC**：CRC16-MODBUS（多项式 `0xA001`），覆盖 `TYPE ~ PAYLOAD`
- **TAIL**：`00 00 80 7F` —— 与 VOFA+ JustFloat 帧尾一致，**所以链路可以先拿 VOFA+ 验证**
- **字节序**：全部小端
- 40 通道遥测整帧 **181 字节**，@50 Hz ≈ **9 KB/s**
